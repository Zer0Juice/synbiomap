Reproducibility

This page explains how to re-run the full pipeline from scratch.

Requirements

  • Python 3.11+
  • API credentials (see .env.example)
# 1. Clone the repository
git clone https://github.com/Zer0Juice/synbiomap
cd synbiomap

# 2. Install dependencies
pip install -r requirements.txt

# 3. Set up credentials
cp .env.example .env
# Edit .env and fill in your API keys

# 4. Run the pipeline (see notebooks/ for step-by-step walkthroughs)

Pipeline steps

The pipeline is a set of numbered scripts under scripts/, each importing logic from src/. The full, ordered list — ingest → embed → cluster → tripartite analysis → robustness and figures — is documented in scripts/README.md. The high-level stages are:

Stage Scripts What it does
Ingest 01–03d Papers (OpenAlex), patents (USPTO / Oldham set), iGEM projects and parts
Embed + cluster 04–07 Base embeddings, UMAP + HDBSCAN, first relatedness test
Fine-tune SPECTER2 build_finetune_data, finetune_specter2, eval_recall_at_k Domain-adapt the embedding model
Tripartite analysis 08–12 Build the three-type corpus, re-embed, cluster, test relatedness
Robustness + figures 13–17 Oldham patent check, regression and robustness tables, figures
Website export 18 Regenerate the Explorer JSON (three artifact types) from the tripartite corpus

Walkthrough notebooks

Notebook What it does
notebooks/pipeline.ipynb Runs the ingest→export steps in order
notebooks/02_tripartite_city_analysis.py (marimo) The main three-type city-level analysis
notebooks/03_carbon_capture.py (marimo) The carbon-capture case study

Configuration

All major parameters (keywords, model name, clustering settings) are in config/settings.yaml. Edit that file to change the pipeline behaviour.

Data

Raw data files are not committed to the repository (too large). Processed CSVs in data/processed/ are committed and can be used to skip the ingestion step.

Rendering the website locally

The Explorer reads five JSON files under website/assets/data/. Regenerate them from the tripartite corpus, then preview:

# Rebuild the three-type Explorer data (no heavy pipeline re-run needed)
python3 scripts/18_export_website_assets.py

# Install Quarto: https://quarto.org/docs/get-started/
quarto preview website/    # live preview
quarto render  website/    # build _site/

Publishing

There is no automated GitHub Action; the site is published manually from the built output:

quarto publish gh-pages website/

## Pipeline steps

The pipeline is a set of numbered scripts under `scripts/`, each importing logic
from `src/`. The full, ordered list — ingest → embed → cluster → tripartite
analysis → robustness and figures — is documented in
[`scripts/README.md`](https://github.com/Zer0Juice/synbiomap/blob/main/scripts/README.md).
The high-level stages are:

| Stage | Scripts | What it does |
|-------|---------|-------------|
| Ingest | `01`–`03d` | Papers (OpenAlex), patents (USPTO / Oldham set), iGEM projects and parts |
| Embed + cluster | `04`–`07` | Base embeddings, UMAP + HDBSCAN, first relatedness test |
| Fine-tune SPECTER2 | `build_finetune_data`, `finetune_specter2`, `eval_recall_at_k` | Domain-adapt the embedding model |
| Tripartite analysis | `08`–`12` | Build the three-type corpus, re-embed, cluster, test relatedness |
| Robustness + figures | `13`–`17` | Oldham patent check, regression and robustness tables, figures |
| Website export | `18` | Regenerate the Explorer JSON (three artifact types) from the tripartite corpus |
